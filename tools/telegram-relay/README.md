# Ретранслятор Telegram

Из российских дата-центров `api.telegram.org` заблокирован, поэтому сайт
(сервер в Москве — так требует 152-ФЗ, база покупателей должна быть в России)
отправляет уведомления через маленький сервер за рубежом.

Боевой ретранслятор: `https://notify.sportliner.store` — Timeweb Cloud, тариф
Cloud NL-15 (Амстердам) + публичный IPv4, всего 1 820 ₽/мес. На нём только Caddy:

- пропускает запросы **только** с IP сервера магазина и **только** для бота
  магазина (`/bot<id бота>:…`), всё остальное — 403;
- ничего не хранит и не пишет в журнал;
- `GET /health` → `ok` — проверка, что он жив.

## Как поднять заново

1. Создать сервер Ubuntu 24.04 за пределами РФ с публичным IPv4. Через API
   Timeweb сервер создаётся без IP: добавьте его (`POST /api/v1/servers/{id}/ips`,
   `{"type":"ipv4"}`) и только потом запускайте cloud-init (переустановкой ОС) —
   без сети `apt` не скачает Caddy.
2. В поле cloud-init вставить `cloud-init.sh`, заменив `__RELAY_DOMAIN__`,
   `__SHOP_IP__`, `__BOT_ID__` (цифры до `:` в токене бота).
3. DNS: A-запись `notify` → IP нового сервера. Caddy сам получит сертификат.
4. Админка → **Настройки** → «Уведомления в Telegram» → «Сервер не видит
   Telegram?» → адрес `https://notify.sportliner.store` → «Подключить».
   Вместо поля можно задать `TELEGRAM_API_BASE` в `.env` сервера.

Сменился бот или IP магазина — поправьте `/etc/caddy/Caddyfile` на
ретрансляторе (`systemctl reload caddy`) или пересоздайте его с новым cloud-init.
